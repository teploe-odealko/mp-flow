# Changelog

## 0.1.0

- Исправлен учёт возвратов Ozon: возвратный posting теперь даёт пару событий — продажу под прежним ключом `ozon-posting-N` и возврат под `ozon-posting-N:return`, поэтому возврат больше не «проглатывается» дедупликацией по общему externalId и не зависает без исходной продажи при бэкфилле. Положительные суммы в финансовых операциях (возврат комиссии и услуг при возврате товара, положительный остаток расчёта) теперь проводятся как компенсации в прочий доход (Дт 76.ТП / Кт 91.01), а не отбрасываются. Уже учтённые по старым ключам возвраты не задваиваются; возвраты, застрявшие в «требует внимания», самоизлечиваются при повторной синхронизации окна — курсор канала старые окна не перечитывает, поэтому для лечения исторических данных запустите синхронизацию с явной начальной датой (backfill).
- Исправлено проведение инвентаризации: `POST /api/inventory/stocktakes` с дефолтным `post` теперь реально применяет эффекты к складу и журналу (раньше — тихий no-op со статусом «posted»); недостача списывается и журналируется по фактической FIFO-стоимости, а не по средней. Миграция 0008 возвращает в черновики инвентаризации, зависшие в «posted» без проводок, — их можно провести повторно.
- Исправлен двойной учёт операционных расходов категорий со счётом 91.02 в P&L: чистая прибыль, нераспределённая прибыль и капитал у затронутых данных вырастут на сумму таких расходов.
- Первый clean-room релиз MPFlow из рабочего контура управленческого учета.
- Проект поднят в корень репозитория без старых экспериментальных подпроектов.
- Добавлены production Dockerfile, compose-конфиги, healthchecks, Prometheus metrics, Grafana dashboards, Loki logs и Sentry-compatible error tracking.
- Добавлены open-source файлы: README, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, issue templates и CI.
