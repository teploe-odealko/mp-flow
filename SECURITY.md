# Security policy

## Как сообщить об уязвимости

Не создавайте публичный issue с секретами, токенами, дампами базы или рабочим exploit.

Для приватного сообщения используйте GitHub Security Advisories в репозитории или напишите владельцам проекта. В сообщении укажите:

- затронутую версию/commit;
- минимальные шаги воспроизведения;
- ожидаемый impact;
- есть ли риск раскрытия персональных данных, marketplace credentials или финансовых данных.

## Поддерживаемая версия

Пока поддерживается только `main`. Исправления безопасности делаются в `main` и выкатываются в production после проверки.

## Авторизация и учетные данные

Авторизация построена на встраиваемой библиотеке better-auth (email + пароль, scrypt-хэширование, серверные сессии в PostgreSQL):

- Регистрация на занятый email никогда не изменяет существующий аккаунт: ответ нейтральный и неотличим от обычной регистрации (анти-enumeration), пароль и сессии владельца не затрагиваются.
- Вход возможен только после подтверждения email; первый владелец инстанса автоверифицируется при owner-setup. При попытке входа без подтверждения письмо со ссылкой отправляется повторно.
- Восстановление пароля: `/api/auth/request-password-reset` → письмо со ссылкой → `/api/auth/reset-password`. После смены пароля все активные сессии пользователя отзываются.
- Rate limiting включен на всех auth-эндпоинтах (вход — 3 запроса / 10 секунд, регистрация — 5 / 60 секунд, запрос сброса пароля — 3 / 60 секунд); счетчики хранятся в PostgreSQL и переживают рестарты.
- Защита от перебора и тайминг-атак: пароль хэшируется даже для несуществующего email; POST-запросы проходят origin-проверку.

## Production-требования

- `AUTH_REQUIRED=true`.
- `BETTER_AUTH_SECRET` задан (длинный случайный, генерация: `npx @better-auth/cli@latest secret`) — без него сервер не стартует.
- Подтверждение email включено.
- `ACCOUNTING_ENCRYPTION_KEY` длинный, случайный и сохранен вне репозитория.
- `DATABASE_URL` указывает на durable PostgreSQL с backup.
- `/metrics` защищен `METRICS_TOKEN`.
- Sentry/GlitchTip и логи не получают cookies, Authorization headers и marketplace API keys.
- Публичная регистрация включается только осознанно.
